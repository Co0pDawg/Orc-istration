# Codex CLI

- **Dispatch:** name the agent in the prompt ("use the `scout` agent to ..."); agents live in `~/.codex/agents/<name>.toml`. Parallel threads are capped by `agents.max_concurrent_threads_per_session`; the High-tier cap of three still applies.
- **Tested named dispatch:** standalone Codex CLI 0.172.0 loaded the generated project-local roles from a trusted project's `.codex/agents/`. With `multi_agent_v2` and `multi_agent_v2_dynamic_tools` enabled, select the exact `agent_type` (for example `builder`) and pass the brief with `fork_turns: "none"` for an ephemeral run.
- **Tiers:** Low `gpt-6-luna`, Mid `gpt-6.1-sol`, High `gpt-6-astra` (`models.json`), with `model_reasoning_effort` from the tier.
- **Board:** local backend only; `install` adds this machine's Board line from `--board <address> --board-repo <path>`, else `board` in `~/.orc/config.json`.
- **Review panel:** no slash command here: follow `review/PROCEDURE.md` in the setup checkout, dispatching the `review-*` agents by name. `metrics capture` reads Claude Code transcripts only, so it is unsupported here.
- **Fallback: one session per role.** Headless runs can use `node tools/orc.mjs dispatch --tool codex --role <name> --brief <file>` (`codex exec --model <model> --sandbox <read-only|workspace-write> [-c model_reasoning_effort="<effort>"] [-c windows.sandbox=mxc] -` with the role body and brief on stdin; `read-only` only for `scout` and `researcher`, which must then report inline because the read-only sandbox cannot write a scratch file; `workspace-write` for every other role, since the refuter runs tests and builds a throwaway worktree and the `review-*` roles write at most an overflow scratch report). On Windows, orc passes `-c windows.sandbox=mxc` for every role to select the MXC sandbox (without a sandbox selection, Codex blocks process launches there; see `docs/example-prompts.md`). Run it inside a git repository: `codex exec` refuses to run outside one unless given `--skip-git-repo-check`, which orc does not pass. An npm install leaves only a `codex.cmd` shim on PATH, which `dispatch` does not start, so set `ORC_TOOL_BIN_CODEX` to the real `codex.exe` under the package's `vendor/.../bin/`. Otherwise, give one Codex session the `developer_instructions` from `agents/builder.toml` and the written spec. Give a fresh session the refuter's instructions, the spec and the diff so it can rerun the tests and return ACCEPT or REWORK with evidence. After rework, run independent review again and read the final diff.
